# Agent Note：Product Design skill preset

状态：已实现

[English](2026-08-31-product-design-skill-preset.md) | 中文

## 问题

DSH 已能提供项目文件、标准编码工具和专用教学工具，但没有覆盖产品调研、界面审计、视觉探索、截图或网址实现、设计验收和受控分享的打包流程。Codex Product Design 插件定义了这套流程，但其实现假定存在 Codex 宿主的已保存上下文、浏览器截图控制、图片生成和托管发布服务。把这些假设直接复制到长期运行的多用户 DSH 进程中，要么会宣传并不存在的工具，要么会把用户设计上下文放入进程全局存储。

## 决策

`@deepseek-ai/dsh-skill-product-design` 在挂载的 skill 层注册十个不可变、可由用户和模型调用的 skill 定义：一个总路由，以及引导、上下文、调研、审计、视觉构思、图片转代码、网址转代码、设计 QA 和分享。定义保留 Product Design 的顺序规则：先检查现有产品上下文和设计系统；匹配或复刻前必须有视觉来源；实现前必须选定视觉方向；在相同视口和状态比较参考与实现；只有在显式请求时才发布。

DSH 版本把宿主集成视为能力，而不是隐含服务。存在时，标准 Web、文件系统、shell 和附件工具可支持调研与实现。没有图片生成工具时视觉构思停止；没有浏览器截图和参考图时视觉 QA 报告阻塞；分享只使用显式批准且已安装的发布目标。skill 禁止伪造可见素材，也不会用文字、ASCII、CSS 绘图或手写 SVG 替代缺失的视觉产物。

持久上下文保存在当前 Session Workspace 内的 `product-design/user-context.md`。技能包不保存进程全局可变状态、凭据或跨项目资料。工作区权限仍由已认证的 DSH 文件系统路径负责，因此现有租户隔离适用于每一次设计上下文读写。

`product-design` 是从标准组装派生的随包 agent preset。它把 persona 替换为产品设计指引，并在现有 skill 文件系统与 Consumer 旁挂载技能包。包贡献受 preset 常驻挂载作用域限制，因此同一进程中的标准会话无法发现 Product Design skill。CLI 把该包声明为解析依赖，使随包组装可以从已安装版本加载。

## 考虑过的替代方案

**原样复制 Codex 插件。** 已拒绝，因为 Browser、ImageGen、Sites、Figma 和已保存宿主上下文属于 Codex 宿主能力，而不是 DSH 服务。没有提供方却宣传这些能力，会产生虚假的完成声明和不可预测的回退。

**在进程用户 home 下保存一份 Product Design 资料。** 已拒绝，因为一个 DSH 进程服务多个认证用户。宿主全局文件会在租户之间共享产品网址、截图和设计偏好。

**只把流程写进一段很长的 persona 提示词。** 已拒绝，因为每次请求都会承担完整 token 成本，用户不能直接调用聚焦阶段，而标准 skill 目录已经负责渐进式发现与加载。

**在同一改动中加入浏览器自动化、图片生成和发布。** 已拒绝，因为三者都是具有独立提供方、授权、数据和部署要求的能力。在部署显式安装它们之前，流程会失败即停止。

## 后果

- 用户可以选择产品设计模式，获得具备标准能力且包含完整 Product Design 流程目录的 agent。
- 产品设计上下文与素材保留在当前私有项目中，并继承现有多用户工作区隔离。
- 技能包可立即用于有来源的调研、代码库审计和根据已提供视觉稿实现；视觉构思与自动对比仍要等到安装兼容提供方后才可用。
- 包测试固定十个定义及护栏，作用域测试证明不会跨 preset 泄漏，无密钥 Web 组装测试在同一进程挂载产品设计与标准会话，并记录 persona 和目录差异。
