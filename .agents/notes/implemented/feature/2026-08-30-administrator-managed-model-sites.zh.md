# Agent Note: 管理员统一模型站点

Status: implemented

[English](2026-08-30-administrator-managed-model-sites.md) | 中文

## 问题

多用户 Web 服务只为一个固定 DeepSeek 模型提供一份管理员凭据。内网部署还可能运行 New API 等 OpenAI 兼容网关，但普通用户不能通过个人设置或进程环境变量安全地共享网关 Key。如果系统向所有用户显示模型路由，却不在请求时鉴权，用户也可以直接构造 RPC 请求来绕过偏好开关。

## 决策

系统设置页保留 `deepseek-official` 站点，并允许管理员从官方适配器声明的模型中选择一个或多个模型使用统一凭据。选择结果存入 `llm-deepseek.sharedModels`；旧设置文件没有该值时，默认使用 `deepseek-v4-flash`。页面还允许管理员添加最多 32 个 OpenAI Chat Completions 兼容自定义站点。管理员填写 HTTP 或 HTTPS Base URL 与 API Key 后，Host 使用 pi-ai 模型发现请求该站点的 `/models` 端点，并提供返回的模型供选择。每个自定义站点保存显示名称、不包含凭据、查询参数或片段的 Base URL，以及最多 32 个已选模型 ID。Host 会分配一个随机的 12 位十六进制站点 ID，并保留对应的 `managed-<site id>` pi-ai 提供方路由。

每个站点都有独立的服务端凭据引用。官方站点使用 `HARNESS_SHARED_DEEPSEEK_API_KEY`，自定义站点使用 `HARNESS_SHARED_MODEL_<SITE ID>_API_KEY`。HTTP 响应只公开凭据是否已配置以及是否可写。创建自定义站点时，系统先写入凭据，再写入 profile；如果 settings 提供方拒绝 profile，系统会移除该凭据。移除站点时会同时移除两项记录。已启用且当前使用任一已选官方模型的 Session 会使用同一个官方站点 Key 完成 DeepSeek LLM 请求与辅助 DeepSeek web 搜索。

一个现有的用户偏好对全部管理员统一站点授权。除非普通用户已启用统一模型且站点凭据已经配置，否则 Gateway 会从该用户的模型目录中移除自定义统一路由。启用该偏好后，没有个人 DeepSeek Key 的用户只能看到管理员选中的官方模型；拥有个人 Key 的用户仍能看到完整官方目录，其中已选模型使用统一 Key，其余模型使用个人 Key。pi-ai、专用 DeepSeek 与 DeepSeek 搜索凭据解析器还会独立解析实时 Session 的项目所有者；如果所有者没有启用统一模型，解析器会拒绝统一凭据。发现操作无需 Session 即可描述路由，但不能使用其凭据生成内容或搜索。

保留的路由与凭据命名文法把本策略和普通 pi-ai 部署 profile 区分开。在通过认证的用户 Session 中，非统一 `apiKeyEnv` 只从该所有者的私有引用 scope 解析；在认证 carrier 之外，它仍保留进程凭据行为。现有 DeepSeek 适配器负责管理员所选官方模型集合的授权。多用户「模型来源」页面仅允许用户轮换官方路由与 DeepSeek 搜索所需的个人 `DEEPSEEK_API_KEY`；端点和统一模型配置仍由管理员持有。

## 验证

Host 路由测试覆盖官方站点凭据替换与模型选择、自定义站点模型发现、创建、更新、删除、输入校验、仅管理员可修改、逐用户凭据隔离，以及提交 Key 不回显。Gateway 测试覆盖所选官方模型的目录投影、个人 Key 保留完整目录、未启用时移除自定义路由、默认模型回退，以及仅所有者可使用的凭据操作与事件。pi-ai、专用 DeepSeek 与搜索组合测试证明，请求会选择 Session 所有者的个人 Key 或明确启用的共享 Key；客户端测试覆盖官方与发现模型的多选、普通用户启用站点，以及只写的个人 DeepSeek 凭据轮换。

## 曾考虑的替代方案

**用一个通用自定义站点记录替换 DeepSeek 官方站点。** 拒绝，因为官方路由拥有专用适配器、已知端点、已声明模型目录和已有凭据数据。保留该站点可以继续使用 DeepSeek 直连行为，自定义站点则使用通用 pi-ai 适配器。

**把一份统一 Key 和 Base URL 存入每位用户的设置。** 拒绝，因为浏览器可见或逐用户复制会增加密钥暴露与轮换工作。管理员为每个站点拥有一份凭据，用户只保存非敏感的启用选择。

**只依赖模型选择器隐藏未启用站点。** 拒绝，因为 RPC 调用方无需使用该选择器即可指定提供方和模型 ID。请求时的所有者授权才是安全决策，目录投影只负责用户体验。

## 后果

管理员可以在单一进程中提供多个 DeepSeek 官方模型和多个内网网关，每位普通用户自行选择这些统一凭据是否用于自己的项目。官方共享 Key 为已选官方模型授权生成与原生 web 搜索；未选官方模型使用用户私有的 `DEEPSEEK_API_KEY`，停用统一模型时全部官方模型也使用个人 Key。因此每项操作都会使用为该模型确定的凭据 owner。共享 Key 保持集中存储并可独立轮换，私有 Key 则按不透明用户 ID 隔离。本设计有意不支持任意提供方协议、手动模型 ID、逐站点用户偏好和用户创建统一路由：自定义统一站点使用 OpenAI Chat Completions、选择 `/models` 返回的模型、共享一个用户开关，并始终由管理员拥有。
