# Agent Note: 管理员统一模型站点

Status: implemented

[English](2026-08-30-administrator-managed-model-sites.md) | 中文

## 问题

多用户 Web 服务只为一个固定 DeepSeek 模型提供一份管理员凭据。内网部署还可能运行 New API 等 OpenAI 兼容网关，但普通用户不能通过个人设置或进程环境变量安全地共享网关 Key。如果系统向所有用户显示模型路由，却不在请求时鉴权，用户也可以直接构造 RPC 请求来绕过偏好开关。

## 决策

系统设置页保留固定的 `deepseek-official/deepseek-v4-flash` 站点，并允许管理员添加最多 32 个 OpenAI Chat Completions 兼容自定义站点。每个自定义站点保存显示名称、不包含凭据、查询参数或片段的 HTTP 或 HTTPS Base URL，以及最多 32 个明确的模型 ID。Host 会分配一个随机的 12 位十六进制站点 ID，并保留对应的 `managed-<site id>` pi-ai 提供方路由。

每个站点都有独立的服务端凭据引用。官方站点使用 `HARNESS_SHARED_DEEPSEEK_API_KEY`，自定义站点使用 `HARNESS_SHARED_MODEL_<SITE ID>_API_KEY`。HTTP 响应只公开凭据是否已配置以及是否可写。创建自定义站点时，系统先写入凭据，再写入 profile；如果 settings 提供方拒绝 profile，系统会移除该凭据。移除站点时会同时移除两项记录。

一个现有的用户偏好对全部管理员统一站点授权。除非普通用户已启用统一模型且站点凭据已经配置，否则 Gateway 会从该用户的模型目录中移除自定义统一路由。pi-ai 凭据解析器还会独立解析实时 Session 的项目所有者；如果所有者没有启用统一模型，解析器会拒绝统一凭据。发现操作无需 Session 即可描述路由，但不能使用其凭据生成内容。

保留的路由与凭据命名文法把本策略和普通 pi-ai 部署 profile 区分开。已有非统一 `apiKeyEnv` 引用保持进程级行为，现有 DeepSeek 适配器也继续执行其专用的统一 Flash 授权。

## 验证

Host 路由测试覆盖官方站点凭据替换、自定义站点创建、更新、删除、输入校验、仅管理员可修改，以及提交 Key 不回显。Gateway 测试覆盖未启用时移除目录条目和默认模型回退。pi-ai 组合测试证明，在项目所有者启用统一模型之前，直接发起的模型请求无法使用统一 Key；客户端测试则覆盖管理员录入站点和普通用户启用站点。

## 曾考虑的替代方案

**用一个通用自定义站点记录替换 DeepSeek 官方站点。** 拒绝，因为官方路由拥有专用适配器、已知端点、固定产品模型和已有凭据数据。保留该站点可以继续使用 DeepSeek 直连行为，自定义站点则使用通用 pi-ai 适配器。

**把一份统一 Key 和 Base URL 存入每位用户的设置。** 拒绝，因为浏览器可见或逐用户复制会增加密钥暴露与轮换工作。管理员为每个站点拥有一份凭据，用户只保存非敏感的启用选择。

**只依赖模型选择器隐藏未启用站点。** 拒绝，因为 RPC 调用方无需使用该选择器即可指定提供方和模型 ID。请求时的所有者授权才是安全决策，目录投影只负责用户体验。

## 后果

管理员可以在单一进程中提供 DeepSeek 官方模型和多个内网网关，每位普通用户自行选择这些统一凭据是否用于自己的项目。Key 保持集中存储，并可独立轮换。本设计有意不支持任意提供方协议、自动模型发现、逐站点用户偏好和用户创建统一路由：自定义统一站点使用 OpenAI Chat Completions、显式列出模型、共享一个用户开关，并始终由管理员拥有。
