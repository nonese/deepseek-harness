# Agent Note: 浏览器访问受管项目文件

Status: implemented

[English](2026-08-29-browser-project-files.md) | 中文

## 问题

已认证门户原先只能通过进入编程运行时来打开受管项目。远程浏览器无法检查或下载该项目生成的文件，而调用操作系统文件管理器只会定位服务器本机，不能向外部客户端提供可用路径。暴露通用主机路径浏览器也会违背[多用户服务器决策](../architecture/2026-08-14-single-process-multi-user-server.zh.md)所定义的按用户项目隔离。

## 决策

每个项目行都会按不透明 workspace ID 打开一个页内同源文件对话框。Host 只在当前已认证用户生成的项目根目录下解析该 ID。浏览器只提交项目相对路径，绝不选择绝对文件系统目标。目录列表会省略隐藏条目和符号链接、拒绝路径越界、限制可见条目数，并只返回相对元数据。文本预览只接受显式文本允许列表中的大小受限普通文件，验证 UTF-8，并通过现有的不可信 Markdown 基础组件渲染 Markdown。下载以附件和 `nosniff` 响应头流式传输一个普通文件。

门户把文件浏览与启动 workspace 会话分开。目录导航、预览、下载、空状态、加载状态和错误状态都保留在同一个居中对话框内；选择可预览文件后，对话框会扩展为文件列表与预览双栏布局。每次请求仍由 Host 作为授权真源，因此账号或 workspace 发生变化后，浏览器中的陈旧项目行也不能跨入其他用户的项目。

## 曾考虑的替代方案

**打开 Finder 或其他原生文件管理器。** 未采用：浏览器可能运行在另一台机器上，而原生操作只会打开服务器桌面，无法返回可供远程使用的文件视图。

**暴露通用服务器目录选择器。** 未采用：该功能只需要在一个已认证受管项目内读取和下载；接受任意起始路径会同时扩大信息披露与授权职责。

**复用只含目录的选择器响应。** 未采用：该响应有意排除文件，也没有预览、下载、文件大小和修改时间语义。扩展它会把不受限的回环地址选择与已认证项目内容访问混在一起。

## 后果

远程用户无需单独配置网络共享或切换到编程会话，就能检查项目生成结果。隐藏文件、符号链接、不支持或过大的预览、目录下载和跨用户 workspace ID 均无法通过该路由访问。条目与预览限制属于部署配置；下载没有应用层字节上限，因此依赖 HTTP 流式传输和部署层传输控制。该 UI 与 Host 路由仍只服务于已认证的多用户 Web 组合。
