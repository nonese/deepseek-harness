# Agent Note: 单进程多用户 Harness 服务

Status: implemented

[English](2026-08-14-single-process-multi-user-server.md) | 中文

## 问题

Web 组合原先假设一个受信任的人操作一个主机账号。浏览器客户端共享进程级 workspace、会话、设置、凭据与事件表面；进程沙箱只约束写入，并且有意允许读取主机文件。因此，只增加登录页只能保护导航，无法形成授权或数据隔离边界。

目标部署是供数十名独立用户长期使用的内网服务。它必须保留文件持久化与单一 Host 进程，不使用每用户容器和外部数据库，并提供管理员与普通用户角色。OIDC 是部署侧集成点，本地凭据则用于测试和紧急访问。

## 决策

Web bundle 组合三个新的能力层：

- `@deepseek-ai/dsh-auth` 定义用户、角色、可撤销的浏览器主体和程序管理的用户路径。
- `@deepseek-ai/dsh-auth-file` 在 `<DSH_HOME>/system/auth` 下保存仅属主可访问且带版本的 JSON 记录，使用带盐 scrypt 哈希本地密码，只保存浏览器令牌摘要，并以稳定的随机标识创建 `<DSH_HOME>/users/<UserId>/...`。
- `@deepseek-ai/dsh-host-auth-web` 持有同源本地与 OIDC 登录、退出、项目和管理员路由。其 OIDC 依赖方使用提供方发现、带 PKCE S256 的 Authorization Code、state、nonce、轮换 JWKS 验证，以及只能消费一次的进程内待完成流程。

浏览器必须先完成认证，才会创建客户端模块系统、激活客户端插件或打开 `/api` 与 WebSocket 传输。公开 index 可以预载不可变 bundle 字节，但排队的 factory 在认证前不会运行。Web 部署会用唯一的持久 Cookie 认证器替换 Connection 的单用户进程令牌认证器，并为 HTTP 与 WebSocket 分发进入 `AuthPrincipal` 请求上下文。有序 Typert Gateway 中间件使用该主体过滤列表与事件流，检查每个可寻址的会话和 workspace，约束项目与目录创建，禁止服务器本地路径操作，并且只接受已在该用户事件流中出现过的审批或问题响应。管理员用户接口只暴露身份元数据，不返回项目或会话内容。

动态 Cordis 插件管理属于管理员能力。普通用户的 API 视图会移除随附的 `cordis` preset，并拒绝任何指定它的会话创建或 preset 选择。Host 上的单调工具守卫会从调用 Agent 的受管项目路径解析当前所有者；除非该所有者仍是管理员，否则拒绝所有 `cordis_*` 执行。Connection Host 会在 Typert interceptor 认领请求之前，拒绝非管理员访问 `dynamicCordisRunner/*` Remote 命名空间。可写的 Agent preset 根目录同样是进程全局资源：普通用户收到的 preset 列表会将其标记为只读，复制或删除调用要求管理员身份。部署配置的 Host 插件仍是进程全局且属于受信任输入；用户在自己项目内安装的包只是该项目中的文件，除非管理员修改部署组合，否则不会成为 Host 插件。

项目统一生成在用户的 `projects` 目录中。用户名和显示名称绝不选择路径，因此修改账号名称不会移动数据，构造的身份文本也不能逃逸数据根目录。现有会话日志、workspace 元数据、附件与 storage 继续使用原有文件提供方；会话所有权由生成项目目录下不可变的规范 `cwd` 决定。这样无需引入 SQLite 或第二种持久化系统即可保留文件存储格式。

管理员统一 DeepSeek Key 通过现有 credentials 提供方保存在专用的 `HARNESS_SHARED_DEEPSEEK_API_KEY` 引用下。认证提供方只把已启用用户的 id 保存到仅属主可访问的 `preferences.json`。每次 `deepseek-official` / `deepseek-v4-flash` 流调用都会由适配器把实时会话路径解析为活动用户，并且只在该用户已启用时选择统一 Key；其他请求继续使用普通凭据路径。只有当该偏好和凭据都处于启用状态时，主体级 `llm.providers` 响应才会把 `deepseek-v4-flash` 标记为统一模型，因此首次使用就绪检查不会要求符合条件的用户填写个人 Key。浏览器 API 只返回是否已配置、是否可写与统一模型 id，绝不返回提交或已存储的 Key。

Web 部署把沙箱默认值与上限固定为 `workspace-write`。持久化的会话覆盖值和手写工具请求都不能超过该上限。模型可见的读取与搜索工具会在 I/O 前执行已认证可读根检查。受限子进程会隐藏完整 Harness home，只重新暴露当前已认证用户的数据树：bubblewrap 使用私有挂载覆盖，Seatbelt 使用读取 deny/allow profile。Landlock 与 Windows ACL 当前无法表达所需读取排除，因此该部署在这两个后端上关闭失败。

认证前 shell 与认证后 portal 只使用可见品牌 `Harness`。登录 shell 把半透明表单面板叠放在一张全画幅海滨插画上：宽视口在右侧保留鲸鱼娘场景，并使用插画中的浅色雾区过渡到表单；窄视口则裁切到这片安静的雾区，使表单保留完整内容宽度。portal 提供私有项目、运行时入口、个人统一模型设置、管理员用户管理、本地密码重置，以及只在服务端报告完整启用配置时可用的 OIDC 登录操作。它会把当前选中的 portal 分区记录在页面查询参数中，因此刷新后会返回运行时或管理分区，而不是重置到项目列表。仅管理员可见的系统页面通过受保护的 Host 路由读取实际生效的进程、存储、认证、隔离、请求限制与统一模型状态；它写入 OIDC issuer、client id、redirect URI、scopes、客户端鉴权方式、首次登录管理员组和可选内网 HTTP 例外，测试提供方发现，并且在不接收已存储值的前提下替换密钥。它不会进入任何用户的 Harness 运行时，也不会提供服务端无法应用的控件。内部包名、环境变量兼容标识和模型提供方名称保持不变。

## 安全边界

Host 进程及管理员为它配置的插件属于受信任计算基，并会影响该进程服务的所有用户。该边界通过传输授权、规范路径检查、子进程约束与仅管理员可用的动态插件控制来隔离用户，但不声称能够抵御管理员作为 Host 插件加载的恶意代码。POSIX 上的认证文件若允许组或其他用户读取会被拒绝，并且多个服务进程不得共享同一认证根目录。

浏览器会话 Cookie 是不透明值，使用 `HttpOnly`、`SameSite=Lax`，并可启用 `Secure`。会修改状态的认证路由要求 Origin 匹配并限制 JSON 请求体大小。停用用户或重置本地密码会撤销该用户的浏览器会话。最后一个启用的管理员不能被降级或停用。

Web CLI 默认绑定回环地址。它的启动提供方在发布配置前会等待认证能力就绪，只有显式传入 `--host 0.0.0.0` 才会把服务开放到局域网。该路径会把本机 LAN IPv4 字面量推导进 Host/Origin 信任栅栏；使用 DNS 名称或别名的部署必须通过 `--trusted-host` 声明。浏览器 RPC 关联值使用 `crypto.getRandomValues()`，因为普通 HTTP 局域网地址不属于安全上下文，不能依赖 `crypto.randomUUID()`。

## 备选方案

**每用户一个容器或进程。** 这种方式能提供更强的操作系统边界，并保留上游单用户假设，但会复制运行时、增加空闲内存，并引入目标内网部署明确拒绝的启动与生命周期管理。

**在单进程中按请求修改 `HOME`。** 环境变量和进程 cwd 都是进程全局状态，而异步用户请求会重叠。修改任一状态都会产生竞态，并可能把一个用户的文件操作路由到另一个用户的数据。稳定的显式路径和主体级服务避免了这种共享可变状态。

**SQLite 或外部身份数据库。** 数据库能提供成熟的事务和查询能力，但会增加部署当前没有的存储技术与运维依赖。通过串行化原子替换的小型属主 JSON 注册表符合现有文件提供方风格和预期用户规模。

**只在前端过滤。** 隐藏行与导航无法保护直接 HTTP、WebSocket、下载、文件系统或命令调用。因此授权位于每个 Host 能力边界，portal 只是该决策的呈现层。

## 后果

一个服务进程现在可以服务互相独立的用户，无需为每个用户启动运行时。文件持久化仍便于检查与备份，用户名变化也不会影响所有权。相应代价是共享 Host 仍属于受信任计算基，认证 JSON 提供方只支持单写进程，并且 Linux 部署需要 bubblewrap 才能提供 shell 读取隔离。缺少强制后端的平台会拒绝模型命令，而不会静默降低隔离强度。

OIDC 非敏感参数和不可变的 `(issuer, sub) → UserId` 绑定继续保存在仅属主可访问的 `oidc.json` 中；客户端密钥通过现有 credentials 提供方保存在 `HARNESS_OIDC_CLIENT_SECRET` 下。首选用户名声明绝不选择已有本地账号，配置的 `groups` 管理员值只在外部身份首次创建时决定角色。当前服务有意不提供协作：项目只属于一个用户，不存在共享或成员模型。身份提供方协议没有上游退出端点，因此 Harness 退出只撤销本地会话。

验证分别覆盖真实认证提供方测试；拒绝匿名用户和普通用户访问系统设置、并证明凭据响应已脱敏的真实 Loader/WebServer/认证 HTTP 组合测试；用于执行发现、PKCE、nonce、JWKS 验证、普通用户创建和重放拒绝的本地签名 OIDC 提供方；已启用、未启用和非 Flash 请求的适配器组合测试；用户级 API 与事件测试；普通用户／管理员动态 Cordis preset、工具守卫与 Remote runner 测试；文件系统符号链接逃逸测试；沙箱 profile 与上限测试；Web shell 测试；以及常规 Web 构建和浏览器主流程。
